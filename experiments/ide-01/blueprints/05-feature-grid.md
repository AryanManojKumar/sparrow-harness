# Blueprint: feature-grid
**File:** `src/components/sections/FeatureGrid.tsx`

Purpose: Explain the harness as a set of concrete, reviewability-focused capabilities that let engineering teams run multiple coding agents against one repository without losing plan, plugin, run, or diff evidence.

Slots: shared_plan_capture · parallel_agent_run_capture · plugin_extension_capture · run_trace_record_capture · review_diff_capture

Structure: The evidence measures one dense feature treatment headed around plugins and traceable runs, but does not establish a card count; for this brief, use five discrete capability cards covering shared plans, parallel agent runs, plugins, traceable run records, and reviewable diffs. Each card has one precise heading, a short two-to-three-line explanation, and one concrete workflow visual: respectively a repository plan with checkpoints, a multi-agent run view, a plugin configuration or extension point, an inspectable run record, and a diff awaiting review. Arrange the cards as a repeatable grid on desktop, with the traceability and review-diff cards treated as the dedicated evidence path; on mobile, reflow to one card per row while preserving that order and keeping each visual attached to its explanation. Do not include a hero claim, testimonial, product tour, pricing, or primary start-free control here; at most, use one secondary text action after the grid so the section explains the system rather than duplicating the neighbouring product-showcase and CTA sections.
