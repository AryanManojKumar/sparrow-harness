# Blueprint: cta
**File:** `src/components/sections/Cta.tsx`

Purpose: Give an engineer an immediate, executable path to start the harness while offering source installation, documentation, and distinct individual and team entry points.

Slots: eyebrow · headline · body · cta_label · source_install_label · quick_start_label · command · command_copy_label · individual_label · individual_body · individual_cta_label · organization_label · organization_body · organization_cta_label

Structure: Build a compact CTA section with one headline, one short body, and a primary try-it-now action paired directly with an install-from-source action, reflecting the two-button start pattern measured in the source examples. Include a clearly labeled Quick Start or documentation route and one executable command that shows how to launch the harness, with a copy affordance rather than turning the command into a feature demonstration. Below or beside the start path, provide two explicitly labeled entry points—For developers and For organizations—with one action for each, as measured in the two-audience CTA pattern. On mobile, stack the start actions, command block, and audience entry points into a single reading order; do not add feature cards, product imagery, workflow steps, or testimonial content because adjacent sections already cover product explanation and proof.
