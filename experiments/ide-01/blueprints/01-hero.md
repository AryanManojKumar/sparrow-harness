# Blueprint: hero
**File:** `src/components/sections/Hero.tsx`

Purpose: Introduce the agent harness by naming its category, stating its developer-preview availability, and giving engineers an inspectable reason to trust it before they start free.

Slots: eyebrow · headline · body · cta_label · secondary_cta_label

Assets:
- One inspectable product capture showing multiple coding agents working against a shared repository plan with a reviewable diff before changes land.

Structure: Use a concise hero hierarchy with one product/category eyebrow, one technical headline, one short body of roughly two to three sentences, one restrained primary CTA labelled for starting free, and one secondary source or inspectable-artifact link. Present the copy beside a single repository or diff capture so the source-oriented proof point is visible without adding a feature list. On mobile, stack the copy and proof capture in reading order, keeping the primary CTA immediately after the body and the source link adjacent to it. Do not include feature cards, testimonials, workflow steps, numbered markers, or a second promotional CTA because those belong to the neighbouring sections.
