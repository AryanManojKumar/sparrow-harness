# drift-test-03 — nothing hand-written

Same brief and blueprints as drift-test-01 and -02. The difference: the design system
was **generated by `design_director`**, not written by me. First run where every design
decision came from the harness.

## Result

| | -01 (subagents) | -02 (harness, my design system) | -03 (harness, generated) |
|---|---|---|---|
| Design system | hand-written | hand-written | **generated, $0.116** |
| Fonts | Geist | Geist | **Barlow Condensed / Public Sans / IBM Plex Mono** |
| Lines | 636 | 706 | 659 |
| Drift findings | 9 | 0 | **0** |
| Visual defects | not run | 3 (real) | **0** |
| Build cost | — | $0.38 | $0.42 (92% cache hit) |

**The two pages look nothing alike**, from an identical brief. That is the design agent
doing its job — the earlier runs were only ever testing whether the builder could hold a
design system, not whether the harness could produce one.

## The signature survived into the build

`design_director` named it: *"a continuous ochre evidence tape labeled with real SOC 2
control IDs, cloud sources and verification timestamps."*

The hero renders exactly that — an ochre band carrying `CC6.1 / AWS IAM / 09:42 UTC /
VERIFIED`, over a control ledger, with `EXHIBIT 01 — EVIDENCE LINEAGE FROM SOURCE SYSTEM
TO CONTROL` set beneath it. IBM Plex Mono carries the control IDs, timestamps and the
evidence hash; Public Sans carries the prose; Barlow Condensed carries the headline. The
builder honoured the mono/body split without being told again.

Its uniqueness pass reported discarding *"a familiar green compliance dashboard with
status pills"* in favour of *"carbon-copy brown, institutional ochre, condensed forms."*
The rendered page is that description.

## Three bugs, all in the harness rather than the model

**1. Nobody composed the page.** The builder writes section files and stops. In -02 I
wired `page.tsx` by hand and never noticed I had. This run shipped the scaffold's
`Hello world!` placeholder, built clean, audited clean, and produced a 7.5KB HTML file
containing `<main>` and two divs. Every section was dead code that still compiled.

`_compose_page` now assembles sections in sitemap order as part of `sparrow build`.
**The gap survived two prior experiments because I had manually papered over it.**

**2. Fonts named by an agent must be loadable.** `design_director` first returned
`"Spline Sans (primary) paired with IBM Plex Mono (evidence metadata)"` — readable prose,
unloadable font. Split into `font_display` / `font_body` / `font_mono`.

Then two Next-specific failures, both surfacing as the same opaque
`Can't resolve 'next/font/google/target.css'`:
- the export is `Barlow_Condensed`, not `BarlowCondensed` — spaces become underscores and
  casing is preserved
- non-variable families **require** an explicit `weight` array; the real message
  ("Missing weight for Barlow Condensed") appears one line below the resolve error

`sparrow tokens` now emits the `next/font` declarations and binds `--font-display`,
`--font-body`, `--font-mono` in `@theme`. The scaffold ships font-neutral.

**3. The audit flagged a compliant builder.** `grid_gap` came back as `"gap-6 md:gap-8"` —
one decision expressed as two utilities. The audit compared whole declared strings against
individual classes and reported 8 false positives. It now splits declared values on
whitespace and strips responsive prefixes on both sides.

## Verdict

End to end with nothing hand-written: brief → design system → tokens + fonts → five blind
section builds → page composition → build → drift audit → deterministic checks → vision
inspection → capture. Clean on both audits.

Total: **$0.54** ($0.12 design + $0.42 build) plus $0.12 inspection.

Still untested: whether a *human designer* would call this good. Two clean audits and a
vision pass that found nothing are evidence of internal consistency, not of taste.
